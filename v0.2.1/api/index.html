6. API Reference¶

The SpiriCamera package provides camera functionality for video capture and frame processing, built into the SpiriSynq ecosystem.

6.1. Classes¶

SpiriCamera — Work with Cameras in SpiriSynq.

class SpiriCamera.Camera(source='', *, quality=80, max_width=1920, max_height=1080, max_framerate=30, mimetype='image/jpeg', synq_topic='', synq_auto_start=True, synq_authoritive=None, **rehydrated)[source]

Bases: CameraBase

A live camera: resolves a source, captures frames, publishes them.

Usage:

cam = Camera("/dev/video0", quality=85)
cam.start()                 # begins the background capture thread
frame_bytes = cam.image     # whatever it has captured so far
cam.stop()

or as a context manager, which starts on entry and stops on exit:

with Camera("testimage://", max_width=1280, max_height=720) as cam:
    frame_bytes = cam.image

Treat a running Camera like a small daemon, not a handle to poll by calling read() yourself: leave start() on its default background=True and let the capture thread run its own loop, paced to max_framerate. To change the rate, set max_framerate — it is live and takes effect on the next frame — rather than calling read() less often. start(background=False) exists for scripted, frame-at-a-time use (tests, one-off captures); it is not the pattern for anything long-running.

This is the authoritative role: actually owning and driving a device. Code that merely wants another process’s frames should not construct a second Camera this way — it should mirror the existing one with from_topic() and either poll image or connect to its psygnal event (cam.events.image.connect(...)); see the “Consuming an existing camera” section of the getting-started guide.

While running, a background thread captures at max_framerate and assigns each encoded frame to image, which publishes it to SpiriSynq. Settings are live: changing max_width, quality, or max_framerate — locally or from a remote peer — takes effect on the next frame without a restart.

An unusable source is not fatal. Construction never raises for a bad source string; the reason lands in camera.source.error and start() is what refuses. This keeps the camera bindable to a live-edited input field.

6. Parameters¶

backgroundbool

Whether to run a capture thread. With False the camera opens but captures nothing until the caller drives read() — useful for scripted, frame-at-a-time use.

A source that resolves but will not open yet – a device that is not plugged in, a spirisynq:// topic nobody publishes yet – does not stop a background camera from starting. It starts waiting: running is true, status reads "waiting for source: <reason>", and the capture thread keeps trying to open the source until it works. The same happens if the source is lost while running.

Report this camera’s lens, as origin knows it.

Either a full pinhole model – width, height, fx and fy, with cx/cy defaulting to the image centre – or just a field of view in degrees, hfov and optionally vfov, which becomes a centred model at the camera’s own frame size once it knows one. Plain numbers rather than an Intrinsics, so a peer that doesn’t have this package (SpiriMav) can call it.

exif_set_tags(provider, tags)[source]

Replace one provider’s tags, leaving every other provider’s.

This is the primitive for more than one piece of software tagging the same camera’s frames without stepping on each other: each provider owns its own bucket, keyed by provider, and setting one never touches another’s. Call it again with the same provider to replace what it set before.

6. Parameters¶

The complete set of tags this provider wants embedded in every frame from now on. An empty mapping is the same as exif_clear_tags(). Unlike exif_update(), a value of "" is kept rather than dropped, which lets a provider that genuinely needs to blank out a built-in tag — omitting source from a frame headed somewhere public, say — do exactly that.

exif_tags_for_frame(frame)[source]

Build the tags to write into the next encoded frame.

The override point for tagging. A subclass with a GPS fix or a gimbal angle to attach on every frame should extend what this returns; a caller or another piece of software adding metadata at runtime should use exif_set_tags() / exif_update() instead, which this merges in afterwards.

Tags come in three layers, each overriding the one before: tags the source says arrived with the frame (frame_tags(), e.g. an upstream camera’s GPS tags through a spirisynq:// source), then this camera’s built-ins, then providers. The built-ins describe the node that produced these bytes, so they replace an upstream’s source and topic – except the capture time, which is kept from the inherited tags when they carry one.

Providers are merged in over the built-ins in sorted-name order, so the result does not depend on which provider happened to register first — but two providers naming the same tag will still resolve in that fixed order regardless, which is worth avoiding by prefixing tag names with something distinguishing rather than relying on.

Dimensions are deliberately absent: the JPEG header already states them, and _on_image_changed() reads them from there. A tag saying something the container also says is a tag that can disagree with it.

class SpiriCamera.CameraBase(synq_topic, synq_base_topic=None, synq_session=<factory>, synq_authoritive=False, synq_lazy_publish=False, synq_publish=True, synq_receive=True, synq_auto_start=True, synq_check_receive_types=True, synq_auto_rehydrate_on_missing_parent_timeout=5.0, synq_mtime=-1, synq_is_deleted=False, _synq_callbacks=<factory>, _synq_last_rehydrate_time=0.0, relative_to='unknown', mount=None, pose=None, _parent_subscriber=None, _parent_pose=None, _parent_live=False, _parent_generation=0, overlay_widgets=<factory>, overlay_client_render=False, source_str='', source=<factory>, vendor='', model='', serial_number='', max_supported_width=None, max_supported_height=None, max_supported_framerate=None, intrinsics=None, received_width=0, received_height=0, received_ratio=0.0, received_framerate=0.0, max_width=1920, max_height=1080, max_framerate=30, quality=80, mimetype='image/jpeg', exif_enabled=True, _exif_tags=<factory>, _exif_timestamp=0.0, _received_frame_at=0.0, running=False, status='stopped', image=b'')[source]

Bases: OverlayMixin, Position

The network-transparent half of a camera.

Every field here is published over SpiriSynq and can be set by a remote peer. Camera adds the behaviour that reacts to those fields; this class is what a mirror on another node sees.

A camera is a Position too: relative_to is what it is mounted on (a gimbal, an airframe) and mount how, so its pose is where it is and which way it looks, in ECEF. Its own frame is FRD: x out of the lens, y to the picture’s right, z down it (see SpiriCamera.projection). A camera that relays another’s frames (spirisynq://) follows that camera’s pose unless it is given its own; one nobody has placed has no pose, and an overlay can’t put anything on its picture by where it is in the world.

The other fields fall into five groups:

source_str / source

What the camera is pointed at. source_str is the request; source is the resolved description, including any error.

vendor / model / serial_number

Device identity, filled in by the source when it can.

max_supported_*

What the source reported when it last opened. Writable like everything else here — nothing in SpiriSynq is truly read-only — though a value set by hand does not reconfigure the device and is overwritten the next time the source opens.

max_width / max_height / max_framerate / quality / mimetype / exif_enabled

The requested capture and encoding settings. These are live: changing them takes effect on the next frame.

received_* / _exif_tags / _exif_timestamp

What the current image turned out to be. See synq_skip_sync and the note below — none of this group goes over the wire as a field of its own.

Tags themselves are not a synced field at all. A caller adds them through Camera.exif_set_tags() / Camera.exif_update() and reads them back from Camera.exif_tags, which is recomputed from image rather than stored and sent.

Note

received_* and the two _exif_* fields describe one specific frame, so they must never be published as fields of their own. SpiriSynq syncs each field independently and promises nothing about two of them arriving together or in order, so a width published beside an image is a width a peer can read against the wrong image. They are instead written into the encoded frame by SpiriCamera.exif and read back out of it, on the authoritative node and on every mirror alike, by Camera._on_image_changed(). A mirror therefore fills these in for itself and stays exact by construction.

The two _exif_* fields carry a leading underscore and sit in synq_skip_sync: the underscore is what actually keeps them off the wire and out of a full rehydrate (SpiriSynq excludes any field named that way unconditionally), and the explicit skip-set entry is only for received_*, which stays public because nothing else needs a leading underscore to keep it from being a field a remote peer could set out from under the image it describes. Read Camera.exif_tags instead of touching _exif_tags directly; the underscore says “computed for you”, not “hidden”.

Note

No field here is read-only, and none should be made read-only. Every one of them is reachable over SpiriSynq, so a remote peer can already write any of them; a property setter or a one-way UI binding would only hide that, not prevent it. Some fields are reported rather than requested — the max_supported_* group especially — but “the source overwrites this on open” is a description of behaviour, not a contract that it cannot be written. Being able to set a field to a deliberately wrong value and watch what downstream does with it is a debugging feature worth keeping.

These are upper bounds, not exact dimensions: a source is free to deliver something smaller, and reports what it settled on through SourceCapabilities.

Note

Do not shorten these to width / height / framerate. The max_ prefix is the contract: a source may answer a request for 1920x1080 with a 640x480 frame and still be correct. class SpiriCamera.SourceBase(url)[source]

Bases: ABC

Abstract base for camera source handlers.

A handler is responsible for its own protocol end to end: deciding whether it recognises a source string, parsing it, opening the underlying device, and producing raw BGR frames. Registration is implicit — SpiriCamera.sources discovers every concrete subclass that has been imported.

Subclasses declare the schemes they own via schemes and implement open(), close(), read(), and is_open. A handler that accepts schemeless strings (such as a V4L2 device path) also overrides handles().
