10.2.3. SpiriCamera.video¶

A camera’s one H.264 encode, and the rate control that suits it to its worst link.

Everything that wants a camera as video reads this one encode, through TransportVideo.packet_received in this process or transport_video/@data_* over SpiriSynq, so however many there are, each frame is encoded once. It suits the worst of them: the lowest target bitrate, frame rate and height cap among the subscribers’ reports.

SpiriCamera.video.VIDEO_CLOCK_RATE = 90000¶

RTP’s clock for video, which VideoPacket.pts counts in.

class SpiriCamera.video.RateController(settings, max_fps)[source]¶

Bases: object

One subscriber’s estimate of what its link will carry.

Every subscriber reports the fraction of frames it lost, about once a second, and each report moves the estimate: cut on heavy loss, grown on clean reports, halved if reports stop. A max_bitrate the subscriber reports itself is kept as a ceiling.

The target stays between min_bitrate and max_bitrate. Below the floor, the estimate is instead met by lowering fps, and the frame is capped to max_height to suit the target.

class SpiriCamera.video.VideoEncoder(camera)[source]¶

Bases: object

Encodes a camera’s raw frames while anything wants them as video.

Runs on its own thread, so a slow x264 holds up neither capture nor JPEG. It always takes the newest raw frame, skipping any it was too slow for.
