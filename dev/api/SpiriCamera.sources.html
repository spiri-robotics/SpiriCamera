6.2.5. SpiriCamera.sources¶

Source handler registry and resolution.

Handlers register themselves simply by being imported: the registry walks SourceBase subclasses and asks each one whether it recognises a given source string. Adding a new protocol means adding a module here — no dispatch table to update, and no protocol-specific knowledge anywhere but the handler itself.

class SpiriCamera.sources.CaptureSettings(max_width=1920, max_height=1080, max_framerate=30)[source]¶

Bases: object

What the camera is asking the source to produce.

These are upper bounds, not exact dimensions: a source is free to deliver something smaller, and reports what it settled on through SourceCapabilities.

Note

Do not shorten these to width / height / framerate. The max_ prefix is the contract: a source may answer a request for 1920x1080 with a 640x480 frame and still be correct. A bare width would read as “the width you will get”, which is a promise no source makes. The names also match the CameraBase fields they are copied from, so the two stay greppable together.

class SpiriCamera.sources.Intrinsics(width, height, fx, fy, cx, cy, origin='')[source]¶

Bases: object

A pinhole camera model, at the resolution it was measured at.

The model is in pixels of a width x height image. A frame of another size with the same aspect – a camera asked for a smaller max_width, say – uses scaled() to that size, rather than the numbers as they are.

Synced as one value, not field by field, so a peer never sees one report’s focal length with another’s size.

class SpiriCamera.sources.SourceBase(url)[source]¶

Bases: ABC

Abstract base for camera source handlers.

A handler is responsible for its own protocol end to end: deciding whether it recognises a source string, parsing it, opening the underlying device, and producing raw BGR frames. Registration is implicit — SpiriCamera.sources discovers every concrete subclass that has been imported.

Subclasses declare the schemes they own via schemes and implement open(), close(), read(), and is_open. A handler that accepts schemeless strings (such as a V4L2 device path) also overrides handles().

class SpiriCamera.sources.SourceCapabilities(max_supported_width=None, max_supported_height=None, max_supported_framerate=None, vendor='', model='', serial_number='', intrinsics=None, frame='')[source]¶

Bases: object

What a source reports it can provide, once opened.

Note

These keep the max_supported_ prefix for the same reason CaptureSettings keeps max_: they are ceilings the device advertises, not a guarantee about any particular frame, and they are copied verbatim onto the matching CameraBase fields.

6.2.5. Attributes¶

Highest framerate the source can deliver, or None if unconstrained.

Device vendor, when the source can determine one.

modelstr

Device model, when the source can determine one.

serial_numberstr

Device serial number, when the source can determine one.

intrinsicsIntrinsics | None

The lens, when the source knows it – a simulated camera does, exactly; most devices don’t say. Its origin is filled in by the camera.

framestr

The SpiriSynq topic of the Position the frames are seen from, when they are some other object’s view: a relayed camera’s. The camera follows its pose unless it has been placed itself. Empty for a source that is the camera.

class SpiriCamera.sources.SourceInfo(url='', scheme='', target='', handler='', error='')[source]¶

Bases: SubSyncableDataclass

Network-transparent description of a camera’s resolved source.

This is the source-shaped half of the camera’s synced state: it travels over SpiriSynq so a remote peer can see what a camera is pointed at without having to parse the source string itself.
