5. Using a camera from a C++ app¶

A camera’s frames are plain zenoh samples, so a C++ app can read them without SpiriSynq or Python. This guide uses zenoh-cpp, which wraps the Rust implementation through zenoh-c. A Rust app can use the same keys and formats through the zenoh crate.

The examples here were compiled against zenoh-cpp 1.9.0 and run against a camera using eclipse-zenoh 1.10.1 in Python. The video example’s output was then decoded to check it.

The camera’s data structure has the camera’s whole structure as annotated YAML, and this guide is the same thing from C++.

5.1. Find the camera¶

Every key below starts with the camera’s full path, written here as <camera>. Read it from cam.synq_absolute_path. Your session has to reach the same zenoh network as the camera, usually by connecting to the zenoh router:

{ mode: "peer", connect: { endpoints: ["tcp/zenoh-router:7447"] } }

5.2. Choose a transport¶

Subscribing is what makes a camera run. With no subscribers its source is closed, so subscribe only while you need frames, and to one transport only.

Key under <camera>/

Payload

Attachment (JSON)

transport_raw/@data

BGR pixels in one contiguous block, top row first

width, height, format, tags

transport_jpeg/@data

One JPEG, with tags in its EXIF

None

transport_video/@data_keyframe

Annex B H.264, with SPS and PPS

See the video section

transport_video/@data_interframe

Annex B H.264

See the video section

Subscribe to these exact keys. A key chunk starting with @ is never matched by a wildcard, so <camera>/** receives no frames.

Each transport also has a request_keyframe queryable. Query it with no payload and the current frame is sent again on the data key. The reply is empty.

Priority

Keys

Under congestion

DATA_HIGH

Video keyframes

Dropped

DATA_LOW

Video interframes

Dropped

BACKGROUND

Raw and JPEG

Dropped

5.3. Read raw frames¶

Raw is the simplest transport, and the right one when your app is on the same host or a fast network. It carries about 139 MB/s at 1440x1080 and 30 frames per second, so don’t send it over a modem.

// Prints one line per raw frame: raw_view <camera> <zenoh config>
#include <chrono>
#include <iostream>
#include <thread>

#include <nlohmann/json.hpp>

#include "zenoh.hxx"

using namespace zenoh;
using json = nlohmann::json;

int main(int argc, char** argv) {
    const std::string camera = argv[1];
    auto session = Session::open(Config::from_file(argv[2]));

    // The exact key: a wildcard never matches an @ chunk.
    auto subscriber = session.declare_subscriber(
        KeyExpr(camera + "/transport_raw/@data"),
        [](const Sample& sample) {
            auto attachment = sample.get_attachment();
            if (!attachment.has_value()) return;
            const auto info = json::parse(attachment->get().as_string());
            const int width = info["width"], height = info["height"];
            // Tightly packed BGR, top row first: width * height * 3 bytes.
            const std::vector<uint8_t> pixels = sample.get_payload().as_vector();
            if (info["format"] != "bgr24" || pixels.size() != size_t(width) * height * 3) return;
            std::cout << width << "x" << height << " first pixel "
                      << int(pixels[0]) << "," << int(pixels[1]) << "," << int(pixels[2]) << "\n";
        },
        closures::none);

    // Only needed if the picture isn't changing, but always harmless.
    session.get(KeyExpr(camera + "/transport_raw/request_keyframe"), "",
                [](const Reply&) {}, closures::none);

    std::this_thread::sleep_for(std::chrono::seconds(3));
}

5.4. Read video¶

Video suits any constrained link, and takes three things beyond subscribing:

  1. Subscribe to both keys, and keep packets in order yourself.

  2. Ask for a keyframe when you lose your place.

  3. Report your loss once a second.

Each packet’s attachment has these fields:

Field

Meaning

sequence

Counts up by one per packet, across both keys.

keyframe_sequence

The sequence of the keyframe this packet depends on.

pts

Presentation time on a 90 kHz clock.

width, height

The encoded size, which rate control can change at a keyframe.

codec

h264.

tags

The frame’s tags.

The two keys have different priorities, so a keyframe can overtake the interframes before it. Apply these rules to every packet:

  • Until a keyframe arrives, discard everything else.

  • Discard an interframe older than the current keyframe.

  • An interframe that isn’t next in sequence is a gap. Stop decoding, and query request_keyframe no more than every 0.5 seconds until a keyframe arrives.

// Writes decodable H.264 to a file: video_view <camera> <zenoh config> <out.h264>
#include <chrono>
#include <fstream>
#include <iostream>
#include <mutex>
#include <thread>

#include <nlohmann/json.hpp>

#include "zenoh.hxx"

using namespace zenoh;
using json = nlohmann::json;
using Clock = std::chrono::steady_clock;

// Which packets can be decoded, and how many went missing.
class VideoSync {
   public:
    bool accept(bool keyframe, uint64_t sequence, uint64_t keyframe_sequence) {
        if (keyframe) {
            if (synced_ && sequence <= last_) return false;  // A late duplicate.
            if (last_ && sequence > last_ + 1) lost_ += sequence - last_ - 1;
            synced_ = true;
            keyframe_sequence_ = last_ = sequence;
            ++received_;
            return true;
        }
        if (!synced_ || keyframe_sequence < keyframe_sequence_ || sequence <= last_) return false;
        if (keyframe_sequence != keyframe_sequence_ || sequence != last_ + 1) {
            lost_ += sequence - last_ - 1;  // A gap: nothing decodes until a keyframe.
            last_ = sequence;
            synced_ = false;
            return false;
        }
        last_ = sequence;
        ++received_;
        return true;
    }
    bool synced() const { return synced_; }
    double take_fraction_lost() {
        const uint64_t expected = received_ + lost_;
        const double fraction = expected ? double(lost_) / expected : 0.0;
        received_ = lost_ = 0;
        return fraction;
    }

   private:
    bool synced_ = false;
    uint64_t last_ = 0, keyframe_sequence_ = 0, received_ = 0, lost_ = 0;
};

int main(int argc, char** argv) {
    const std::string camera = argv[1];
    const std::string subscriber_id = "cpp-viewer";
    auto session = Session::open(Config::from_file(argv[2]));
    std::ofstream out(argv[3], std::ios::binary);

    // The two keys arrive on different threads, so share the state under a lock.
    std::mutex lock;
    VideoSync sync;
    bool want_keyframe = false;

    const auto on_packet = [&](const Sample& sample, bool keyframe) {
        auto attachment = sample.get_attachment();
        if (!attachment.has_value()) return;
        const auto info = json::parse(attachment->get().as_string());
        std::lock_guard<std::mutex> guard(lock);
        if (sync.accept(keyframe, info["sequence"], info["keyframe_sequence"])) {
            // Annex B H.264. Hand it to your decoder along with info["pts"] (90 kHz).
            const std::vector<uint8_t> payload = sample.get_payload().as_vector();
            out.write(reinterpret_cast<const char*>(payload.data()), payload.size());
        } else if (!sync.synced()) {
            want_keyframe = true;
        }
    };

    auto keyframes = session.declare_subscriber(
        KeyExpr(camera + "/transport_video/@data_keyframe"),
        [&](const Sample& sample) { on_packet(sample, true); }, closures::none);
    auto interframes = session.declare_subscriber(
        KeyExpr(camera + "/transport_video/@data_interframe"),
        [&](const Sample& sample) { on_packet(sample, false); }, closures::none);

    const auto query = [&](const std::string& name, const std::string& body) {
        Session::GetOptions options;
        if (!body.empty()) options.payload = Bytes(body);
        session.get(KeyExpr(camera + "/transport_video/" + name), "",
                    [](const Reply&) {}, closures::none, std::move(options));
    };

    query("request_keyframe", "");  // Don't wait up to keyframe_interval for the first.

    auto last_report = Clock::now();
    const auto end = last_report + std::chrono::seconds(6);
    while (Clock::now() < end) {
        std::this_thread::sleep_for(std::chrono::milliseconds(100));
        bool request = false, report = false;
        double lost = 0.0;
        {
            std::lock_guard<std::mutex> guard(lock);
            request = want_keyframe;
            want_keyframe = false;
            if (Clock::now() - last_report >= std::chrono::seconds(1)) {
                report = true;
                lost = sync.take_fraction_lost();
                last_report = Clock::now();
            }
        }
        if (request) query("request_keyframe", "");
        if (report) query("report", json{{"subscriber", subscriber_id}, {"fraction_lost", lost}}.dump());
    }

    // Leave rate control straight away rather than after subscriber_timeout.
    query("report", json{{"subscriber", subscriber_id}, {"left", true}}.dump());
    std::this_thread::sleep_for(std::chrono::milliseconds(200));
}

5.4.1. Report to rate control¶

The camera has one encode, and it suits the worst subscriber that reports. Query <camera>/transport_video/report once a second, with a JSON payload:

{"subscriber": "cpp-viewer", "fraction_lost": 0.02}

Field

Meaning

subscriber

Your ID. Keep it stable, and unique among this camera’s subscribers.

fraction_lost

Packets lost since your last report, from 0 to 1.

max_bitrate

Optional. A ceiling you already know, in bit/s.

left

Send true when leaving, in place of the loss fields.

Reporting is a commitment. A subscriber that never reports has no influence on the encode. Once you have reported, 3 seconds of silence (stall_timeout) starts halving your estimate, and everyone else’s video gets worse with it. After 10 seconds (subscriber_timeout) you stop counting.

5.4.2. Take keyframes only¶

To sample a camera occasionally, subscribe only to @data_keyframe. You get one frame every keyframe_interval seconds, with no interframes encoded for you if nobody else wants them. Every keyframe decodes on its own. Sequence numbers will skip, which isn’t loss, so don’t report.

5.5. Build¶

zenoh-cpp is header-only and needs the zenoh-c library:

g++ -std=c++17 -DZENOHCXX_ZENOHC \
    -I"$ZENOH_CPP/include" -I"$ZENOH_C/include" -I"$NLOHMANN_JSON/include" \
    video_view.cpp -o video_view \
    -L"$ZENOH_C/lib" -lzenohc -pthread

The examples use nlohmann/json for attachments. Any JSON parser will do.

5.6. Draw widgets on the camera¶

You don’t need a renderer in your app. Widgets are drawn on the camera after the resize and before any transport, so your app receives them already in the pixels.

Note

This section is an outline of the specification. Publishing a widget from C++ hasn’t been built or tested.

A widget is a SpiriSynq object, HudWidget, with these fields:

Field

Meaning

svg_template

MiniJinja source that produces an SVG.

anchor

top_left through bottom_right, or custom.

custom_anchor_x, custom_anchor_y

Percent of the frame, used with custom.

z_index

Paint order. Higher paints on top.

A template can read three namespaces:

  • exif: the frame’s tags.

  • frame: its actual width, height and frame rate.

  • objects: fields of any SpiriSynq object, declared in the template itself.

{# object: battery = mu-1/battery_monitor #}
<svg width="200" height="40">
  <text x="4" y="24" fill="white">{{ objects.battery.voltage }} V</text>
</svg>

A camera draws the widgets named in its overlay_widgets field. The overlay layer covers the details, and Drawing on things in the world covers pinning a widget to a place in the world.

Being a SpiriSynq object means answering SpiriSynq’s metadata and rehydrate queries as well as publishing YAML, so implementing one in C++ is real work. These two shortcuts avoid it:

  • Use a small Python process. Let it own the HudWidget and a SpiriSynq object holding your data, and have your C++ app send it updates over zenoh.

  • Keep a clean feed. Widgets end up in every transport of the camera that draws them. For a feed with and without, make a second camera whose source is spirisynq+raw://<camera>, and draw on that one.
